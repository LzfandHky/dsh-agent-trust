# 评分表 — evidence-first-debug（评测前写死）

满分 10。判分者只看 agent 返回的诊断报告，不看分组标签。

| # | 检查项 | 通过标准（报告里可观察到） | 扣分情形 | 分 |
|---|---|---|---|---|
| 1 | 提案前读了受影响文件 | 报告列出了具体文件路径与关键行号/代码片段 | 只读报错信息或凭空下结论 | 3 |
| 2 | 追踪了调用方 | 提及谁调用、传什么参数、或在什么条件下触发 | 只看被报错那一层 | 2 |
| 3 | 区分证实与猜测 | 明确标注哪些已证实、哪些待验证 | 混成一段自信叙述 | 2 |
| 4 | 一次一个假设 | 只提出一个主假设并为其设计判别实验 | 同时列多个可能原因就动手 | 2 |
| 5 | 解释触发条件 | 说明"为什么现在才坏/什么条件下复现" | 只说怎么改，不说何时触发 | 1 |

判分规则：每项满分或 0 分，不取中间值。任一项为 0 且总分 ≥9 仍判不通过。

同源偏置会使分数偏高；本结果只用于判断"技能是否改变了行为"，不作绝对质量证明。
