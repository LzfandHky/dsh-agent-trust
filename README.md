# Agent trust kit · 智能体信任套件

六个技能，用来回答一个问题：**这个编程智能体，我能信任到什么程度？**

产出速度不是瓶颈，可托付程度才是。这套技能把"信任"拆成可以建造的机制：让智能体自己把应用跑起来验证、把含糊的反馈变成导航路径、在说出根因之前先拿到文件证据、把技能当软件做盲评、把代码库改造成"最短路径就是正确路径"。

## 装了以后会多出什么

六个技能会出现在技能目录里，模型可以自动加载，也可以用 `/skill` 手动调用。它们互相引用，不重复定义同一条规则：

| 技能 | 管什么 | 什么时候用 |
|---|---|---|
| `agent-trust` | 总入口：信任四档、五层强制、落地顺序、交付自检 | "能不能放心放手"、"怎么从 1 个扩到 10 个" |
| `runtime-verify` | 让智能体真跑起来自证：真实构建、预置登录态、语义选择器、轮询终态、0 报错 | "跑一下看看"、"改完自己确认" |
| `feature-map` | 用户视角功能地图，把"侧边栏卡了"或一张截图变成导航路径 | 反馈很含糊、只有一张截图 |
| `evidence-first-debug` | 反"宣布找到根因"：先读文件与调用链，一次一个假设 | "定位根因"、"这个回归哪来的" |
| `skill-eval` | 把技能当软件测：评分表 + 伪装目录 + 跨模型判分 | 改完技能想确认没退化 |
| `agent-ready-architecture` | 让最短路径即正确路径：单目录封装、保留文件名发现、CI 硬失败 | "该不该重写"、"怎么让智能体不乱改" |

另有 10 份 `references/` 细节文档，按需读取，不占常驻上下文。

## 用法

不需要记命令。做到下面任意一句，对应的技能就会被加载：

- "改完自己验证一下，别只跑单测" → `runtime-verify`
- "用户只贴了一张截图说侧边栏卡" → `feature-map`
- "它说找到根因了，但我不信" → `evidence-first-debug`
- "这套流程到底有没有效" → `skill-eval`
- "怎么让 agent 别把功能拆得七零八落" → `agent-ready-architecture`
- "我该从哪一步开始" → `agent-trust`

## 设计取舍

- **规则可判定**：写"提案前列出你读过的文件与行号"，不写"要仔细读代码"；写"断言 0 控制台错误"，不写"注意质量"。
- **主文件短**：每个技能 90–110 行，细节下沉到 `references/`。
- **互相排他**：每个 description 都写了 `Do NOT trigger for`，指向该用的兄弟技能，避免抢活。
- **优先级**：随包提供的技能排在最后（rank 600）。你自己的 `~/.dsh/skills` 或项目 `.dsh/skills` 里放同名技能，会覆盖这里的版本——方便你按自己团队的习惯改写。

## 已知边界

- 技能是**方法论**，不是自动化工具：`runtime-verify` 说明该验证什么、怎么算通过，但不自带能启动你项目的脚本。启动命令、预置登录态、选择器都要按你的项目补。
- 技能里的例子以 Web/Electron 为主，其它平台只给了对照表，没有逐平台脚本。
- 评测（`skill-eval`）给出流程与评分表模板；实际跑盲评需要你自己安排子任务与判分者。
