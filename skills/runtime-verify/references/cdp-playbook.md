# 浏览器 / Electron 运行时验证要点

面向 Web 与 Electron 应用的自动化验证。核心是把"人能看见的"变成"agent 能断言的"。

## 启动阶段

| 步骤 | 做法 | 判据 |
|---|---|---|
| 探活 | 启动前先检查工具链与调试端口是否可用 | 端口可连、版本命令返回正常 |
| 启动 | 以开发模式或已打包产物启动，固定一个已知端口 | 进程存活、目标地址返回 200 |
| 登录态 | 复用一份预先登录好的用户数据目录（可克隆覆盖） | 打开即处于登录态，无登录页 |
| 清场 | 关掉残留的弹窗、引导浮层、通知；恢复默认分组 | 主界面干净、可直达目标 |

**登录态是最容易被低估的成本。** 每次让 agent 走一遍 OAuth 都是浪费，而且经常因为验证码/2FA 卡死。
准备一份"已登录的用户数据目录"，验证时复制过去。

## 观测顺序

1. **先取结构**（无障碍树 / 语义树）→ 拿到可点击、可填写的元素与其稳定标识。
2. **再动作**：每次只做一个会改变页面的动作，动作后立刻断言预期结果。
3. **取不到就重取结构**，不要用旧标识重试第二次。
4. **截图只在需要视觉证据时用**（画布、图表、渲染异常）；结构能读就用结构。

## 等什么

不要等固定时间，等**可观测的终态**：

- 元素出现/消失/可用。
- 文本或某个属性变成期望值。
- 某个网络请求返回且状态码正确。
- URL 变为目标路由。
- 流式输出"停止增长"（连续两次采样长度不变）。

固定等待只用于纯动画过渡，且要短。

## 断言要点

- **0 控制台错误**是可交付的硬指标：验证全程收集控制台，交付时给出错误数。
- 每个关键动作后至少一条断言，不要"点完就算完成"。
- 断言失败要保留当时的页面状态快照，而不是只回一句"失败了"。

## 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 选择器频繁失效 | 依赖 CSS 类名 | 改用 role/aria-label/data-* 属性 |
| 点击没反应 | 元素被浮层挡住 / 需要触摸事件 | 先关浮层；触摸优先的页面用 touch 方式点击 |
| 动作后拿不到新状态 | 用了旧的结构快照 | 重新取结构，旧标识不要复用 |
| 跨域 iframe 内元素定位不到 | CSS 选择器不跨 iframe | 用结构快照给出的元素标识定位 |
| 打开新标签/弹窗后失控 | 目标切换了 | 动作后先列出标签页，确认目标再继续 |
| 数据脏导致结论错 | 上一轮测试残留 | 每轮开始重置数据或用独立账号 |

## Electron 额外注意

- 渲染进程与主进程日志要分别收集，很多问题只出现在主进程。
- 性能验证看长任务是否超过每帧预算（60 FPS → 每帧 16ms）；超预算即使用户"感觉还行"也是回归。
- 内存问题用堆快照对比，别用"看起来卡"下结论。

## 一条最小可用验证脚本的骨架

```
1. 探活 → 启动 → 等目标地址可达
2. 载入预置登录态 → 等主界面就绪元素出现
3. 清场（关弹窗/浮层）
4. 依次执行：导航 → 动作 → 断言（每个动作一条断言）
5. 汇总控制台错误、耗时、失败步骤
6. 输出证据包（见 verification-report.md）
```

脚本要能被重复运行且幂等：第二次运行不能因为第一次留下的状态而失败。
