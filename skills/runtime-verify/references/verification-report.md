# 验证报告（证据包）模板

交付时直接填空。**没有填满的报告不算验证。**

```markdown
## 验证报告

- 任务：
- 结论：通过 / 不通过 / 部分通过（未验证项见末节）
- 时间与环境：

### 1. 如何运行
- 启动命令：
- 目标地址 / 入口：
- 依赖前置（是否需要数据库、密钥、预置数据）：

### 2. 复现（修改前）
- 步骤：
- 现象：
- 证据：<日志片段 / 截图路径 / 报错文本>

### 3. 验证（修改后）
- 相同步骤：
- 现象：
- 证据：<同上>
- 持久化检查：<刷新/重进/读接口是否仍为新值>

### 4. 自动化检查
- 回归测试：<命令> → <结果>
- 相关既有测试：<命令> → <结果>
- 静态检查（lint/类型/依赖图）：<命令> → <结果>

### 5. 运行时观测
- 控制台错误：0（或：N 条，如下）
- 性能/内存：<若有预算，给出实测 vs 预算>
- 其它日志：（主进程/服务端）

### 6. 改动范围
- 文件：
- 是否原子可回滚：是/否
- 回滚方式：

### 7. 未验证项
- <项> — 原因：<无环境 / 无权限 / 依赖外部服务 / 时间不足>
```

## 填写纪律

- "未验证项"必须显式列出，宁可长也不要空着。
- 不要写"应该""大概""理论上"；写"观察到 / 没观察到"。
- 证据优先给**命令与原始输出**，其次截图，最后才用自己的描述。
- 如果验证过程中发现新问题，单独列一节，不要混进结论。
- 结论为"通过"的前提是：第 3 节与第 4 节都有实证，且第 5 节错误为 0 或已解释。

## 反面示例（不要这样写）

```
✅ 已修复该问题，测试通过。
```
问题：没有步骤、没有证据、没有说哪个测试、没提未验证项。

```
⚠️ 应该没问题了，你试一下。
```
问题：把验证责任推回给人，等于没做验证。
