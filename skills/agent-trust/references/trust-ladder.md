# 信任阶梯详解

## L0 人肉传声筒

**你在做什么**：打开应用、点几下、看到报错、截图、粘进对话、等修改、再重复。
**为什么慢**：agent 看不见自己产出的结果，你是唯一的 I/O 设备。你不是在管理，是在当传感器。
**识别信号**：

- 一小时内你在同一件事上来回粘贴 5 次以上截图。
- 你说过"你再试一下"、"还是不行"、"这次报错变了"。
- 你的并发数恒等于 1。

**唯一正确动作**：停止优化提示词，去建运行时验证（`runtime-verify`）。

## L1 有验证的本地观察

**状态**：agent 能自己启动程序、自己操作、自己读日志、自己判断成败。
**你还在做的事**：全程盯着，但盯的是它的结论而不是每一步操作。
**典型时长**：几周到一两个月（取决于项目是否能跑起来）。
**离开条件**：

- 至少 3 个真实问题由 agent 独立复现并独立修好，你没有给过界面信息。
- 它有"跑不起来的判定"能力：环境缺依赖时明确说无法验证，而不是蒙一个结论。

**此时该做的第二件事**：一边看它干活，一边记它复发的毛病（→ `evidence-first-debug` 与 `skill-eval`）。

## L2 局部放手

**状态**：你不再逐行读代码，改看"证据包"——复现前后对比、验证输出、改动清单、回滚方式。
**前置条件（缺一不可）**：

- 关键不变量已经写进硬检查（lint/CI/依赖图）。
- 改动被切分为可独立回滚的原子单元。
- 存在一条能自动跑的用户路径验证。

**识别你已到位**：你审一个 PR 的注意力从"这行对不对"变成"它证明了吗"。

## L3 无人值守

**状态**：过夜合并，次日巡检，异常才介入。
**代价**：必须先有 L2 的全部条件，加一条——**事后可观测性**：合并后能自动/快速发现回归。
**风险控制**：

- 只对"有实时验证 + 依赖图 CI + 可立即回滚"的原子改动开放。
- 保留"早上看一眼"的巡检习惯；无人值守不等于不负责。
- 记录一次夜间合并的回滚率；它比 PR 数更能说明你把事做成了没有。

## 升降级判据速查

| 想升级 | 先证明 |
|---|---|
| L0→L1 | agent 能在无人工干预下看到自己操作的结果 |
| L1→L2 | 硬检查能挡住三类已知的错误写法 |
| L2→L3 | 一次夜间合并后，你能在 10 分钟内定位并回滚任何一条 |
| 任意降级 | 出现"同一问题修了三次还在"——立刻回到上一档补机制 |

## 一个反直觉的点

并发数不是能力指标，是**机制完备度**的副产品。先问"我能不能在不看的情况下判断这次改动没退化"，
再问"我能同时跑几个"。顺序反过来，就是在用钱买教训。
