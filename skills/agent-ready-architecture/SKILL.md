# 为智能体而建的架构

## 出发点：把"抄近路"当设计输入

写代码的 agent 有五个稳定的习惯，不要试图用提示词消灭它们，要**让它们导向正确结果**：

1. 复制最近的可用写法。
2. 改当前打开的那个文件。
3. 选能编译的最短路径。
4. 不敢删调用方看不见的代码。
5. 照做提示，即使它违反系统不变量。

由此得到唯一的设计目标：**让最短路径就是正确路径。**

## 五条设计规则

| # | 规则 | 落地表现 |
|---|---|---|
| 1 | 常规路径比近路**更省事** | 新建功能只需建一个目录、填一个保留文件名 |
| 2 | 禁止的依赖**机械失败** | 依赖图 CI 直接红，不靠人提醒 |
| 3 | 每个持久值**只有一个写入者** | 客户端状态走命名 hook/命令，别处不许直写 |
| 4 | 新功能**加隔离文件**，不在共享根上加分支 | 避免十几个并行 agent 改同一文件冲突 |
| 5 | 例外**少、显式、按架构变更评审** | 有豁免清单，且豁免本身要评审 |

规则 4 是多 agent 并行的关键：共享注册表是并行冲突的放大器，
"保留文件名自动发现"能把它拆掉。

## 五个公共名词（可按你的技术栈替换）

- **Feature**：一个目录装下某功能约 80% 的代码，不需要全局搜索。
- **Entrypoints**：入口显式声明，不藏在隐式注册里。
- **Cards/Modules**：由保留文件名自动发现，不需要中央注册表。
- **Client**：客户端持久状态的唯一写入者，对外是命名命令。
- **Host**：一个类型化契约；框架层永不反向 import 产品层。

名词不用照抄，要照抄的是"**少的、可预测的、被结构保证的几个概念**"。

## 硬检查清单（优先做这几条）

| 检查 | 拦住的失败 |
|---|---|
| 禁止某些高危 API（如渲染层副作用钩子） | 级联重渲染、状态同步 bug |
| 禁止新增代码注释 | 把对话历史写进代码，污染后续上下文 |
| 主进程/渲染进程依赖图隔离 | 重计算被拖进每帧预算，掉帧 |
| 层间单向依赖（框架 ↛ 产品） | 循环依赖、改动涟漪 |
| 原子改动（禁止巨型 PR） | 无法定位、无法回滚 |

关于"禁注释"：意图不是禁止一切说明，而是禁止**闲聊式/历史式注释**。
真正的不变量（协议、加密、法规要求）写进受评审的架构文档，而不是散落在代码里。

## brownfield 与 greenfield 的差别

| 类型 | 现状 | 策略 |
|---|---|---|
| 成熟大仓 | 已有面向"最不熟练贡献者"的护栏（凭据边界、框架约束） | agent 直接受益，补关键禁止项即可 |
| 快速原型（vibe 出来的） | 无护栏，agent 一路抄近路，形成"有机架构" | 值得大规模重构；投入换长期可托付 |

判断要不要重写，别问"代码丑不丑"，问：**现在能不能让 15 个 agent 并行改而不互相摧毁？**

## 落地顺序

1. 收敛一个功能到一个目录（先挑最常被改的那个功能）。
2. 加依赖图 CI（先只禁最疼的一条）。
3. 把最近 3 条人工评审意见转成 lint/AST 规则。
4. 引入保留文件名自动发现，删掉一个中央注册表。
5. 重复 1–4，直到"新建功能"不需要思考放哪。

每一步都要能独立提交、独立回滚。

## 代价与取舍

- 约束越多，人手写代码越烦——但**agent 会吸收这些麻烦**，这才是收益来源。
- 一旦硬检查就位，日常任务不再需要最强模型，小模型也能在护栏内写出合规代码。
- 前期投入大（可能抵数百个 PR），单人或小团队要按 ROI 排优先级，别一次全上。

## 与其它技能的衔接

- 决定"写进结构还是写进技能" → `agent-trust` 五层强制
- 改完要验证没退化 → `runtime-verify`
- 想确认新规则真的生效 → `skill-eval`（把规则当被测对象）
