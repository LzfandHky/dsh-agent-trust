# 假设台账

多个假设并行时用它，避免"改着改着忘了在验证什么"。

```markdown
# 假设台账 — <问题标题>

现象：<一句话>
复现：<步骤>

| # | 假设（具体到位置与机制） | 判别实验 | 预期 | 实际 | 状态 |
|---|---|---|---|---|---|
| 1 | 依赖数组漏 sessionId（file.ts:52） | 切会话并打印 sessionId | 打印旧值 | 打印旧值 | 已证实 |
| 2 | 接口缓存了旧响应 | 抓包看请求 URL | URL 含旧 id | URL 正确 | 已推翻 |
| 3 | 渲染层读错切片 | 打印 selector 结果 | 返回旧会话 | — | 未验证 |

## 结论
根因 = #1。改动 = 补依赖 + 加回归测试。
#2 推翻的依据：<证据>
#3 暂不验证，因为 #1 已解释全部现象（若修复后仍复现，回到 #3）
```

## 使用纪律

- 一行一个假设，**不要合并**。
- "状态"只能是四种：未验证 / 已证实 / 已推翻 / 无法验证。
- 已推翻的假设也要留着，附上推翻依据——它防止下次重复挖同一条。
- 修复后如果现象仍在，检查是不是漏了某个"未验证"行。
- 结束时不删台账，把它挂在问题记录里；同类问题下次能省一半时间。
